# Заметки по Vercel

Почему конфигурация именно такая. Всё ниже выяснено деплоями, а не чтением документации.

## `"framework": null`

Держит проект статическим сайтом с Python-функциями. Если оставить автоопределение, Vercel
видит FastAPI, считает проект бэкендовым целиком и перестаёт отдавать `web/dist` — фронтенд
начинает возвращать 404.

## `/api` переписывается на функцию — и это обязательно

`api/index.py` сам по себе обслуживает только путь `/api/index`. Чтобы до FastAPI доходили
`/api/health` и остальные маршруты, нужно правило `/api/(.*) → /api/index`. Без него всё
под `/api` отвечает 404 — проверено.

В логе сборки при этом висит предупреждение:

> Internal rewrites in backend framework projects now route requests using the rewritten
> destination path.

К нам оно **не относится**, потому что у нас `"framework": null` — проект не считается
бэкендовым, и функции приезжает исходный путь. Но если когда-нибудь захочется убрать
`framework: null`, сломается сразу и это тоже: FastAPI начнёт получать `/api/index`.

## Зависимости — только `pyproject.toml`

Vercel ставит их через **uv**, и `pyproject.toml` для него главнее. Отсюда два следствия,
на которых мы обожглись:

- `requirements.txt` в корне просто игнорируется;
- `uv sync` берёт **базовые** зависимости и не берёт экстры. Пока зависимости лежали
  в `[project.optional-dependencies]`, функция уезжала в деплой без единой из них.

Поэтому всё, что нужно приложению, лежит в `[project.dependencies]`.

## `[tool.vercel] entrypoint` не работает с layout `src/`

Он резолвит `module.path` как **файл от корня проекта**, а не как установленный модуль.
`padel_tour.api.app` ищется как `padel_tour/api/app.py` в корне и не находится. Поэтому
точка входа — `api/index.py`, конвенциональное место.

## uvicorn в деплой не едет

Vercel сам поднимает ASGI-приложение, свой сервер ему не нужен. `uvicorn` лежит в dev-группе
и служит только для локального `uv run uvicorn padel_tour.api:app`.
