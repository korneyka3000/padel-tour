## Блокирует сейчас: доступ к GitHub

Коммиты копятся локально, `git push` падает:

```
git@github.com: Permission denied (publickey)
```

Ключ `~/.ssh/id_ed25519` на месте, но GitHub его не принимает, а ssh-агент в сессии не
поднят. Заодно протух токен `gh` (`gh auth status` → *The token in default is invalid*).

Любой из вариантов подойдёт:

```
! ssh-add ~/.ssh/id_ed25519 && git push -u origin main
```

или, если ключ вообще не привязан к аккаунту:

```
! gh auth login
```

После этого скажи — запушу.

## M2 — база данных

**Рекомендую [Neon](https://neon.tech)**: у тебя уже подключена интеграция с Neon в этой
сессии, значит проект и ветки БД я могу завести сам, без ручной возни. Serverless Postgres,
бесплатного тарифа с запасом хватит.

От тебя: подтвердить, что заводим проект в Neon, и в какой организации.

Что появится:

```
DATABASE_URL=postgresql://…      # прод-ветка
DATABASE_URL_TEST=postgresql://… # ветка для тестов, сбрасывается перед прогоном
```

Локальная разработка пойдёт на SQLite без всякой настройки — Postgres нужен там, где
приложение реально живёт. Схема одна, миграции через Alembic.

**Ветки Neon дают приятный бонус:** можно создавать ветку БД на каждый PR и гонять
миграции на копии реальных данных, а не на пустой базе.

## M3 — Telegram-бот

**Токен.** Пишешь [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username.
Он выдаёт строку вида `1234567890:AA…`. Это `BOT_TOKEN`.

Заодно сразу полезно:

- `/setdomain` — понадобится в M5 для входа через Telegram, но проще выставить сразу
- `/setcommands` — список команд, чтобы бот выглядел живым
- **выключить** privacy mode не нужно: бот работает в группе через свои команды и
  инлайн-кнопки, читать чужие сообщения ему незачем

**Webhook или polling.** Начнём с polling — он не требует ни публичного адреса, ни
сертификата, и его достаточно для группы. Переезд на webhook — одна настройка, когда
появится постоянный хостинг; тогда добавится `TELEGRAM_WEBHOOK_SECRET` (генерю сам).

**Важно про доступность.** Сервер обращается к `api.telegram.org`, поэтому хостинг должен
стоять там, откуда Telegram доступен. На пользователей в России это не влияет ровно
настолько, насколько у них самих работает Telegram — и именно поэтому веб с входом по почте
(M5) не роскошь, а обязательная вторая дверь.

```
BOT_TOKEN=1234567890:AA…
TELEGRAM_WEBHOOK_SECRET=…   # только когда перейдём на webhook
```

## M3–M4 — хостинг

Решаем в M3, но подумать стоит сейчас, потому что от этого зависит форма деплоя.

| Вариант | Плюсы | Минусы |
|---|---|---|
| VPS + docker compose | всё в одном месте, polling работает без плясок, дёшево | ты администрируешь сервер |
| Fly.io / Railway | деплой из git, не надо администрировать | привязка к платформе |
| Vercel (фронт) + отдельный бэкенд | фронт бесплатно и быстро, у меня есть готовый скилл для деплоя | бота на Vercel не поселить — нужен второй хостинг |

Мой выбор — **фронтенд на Vercel, API и бот на одном небольшом VPS или Fly.io**. Postgres
в Neon в любом случае снаружи, так что сервер держит только приложение.

Для Vercel нужен будет `VERCEL_TOKEN` (Settings → Tokens), для VPS — ssh-доступ.

## M5 — аккаунты

**Почта.** [Resend](https://resend.com) — самый простой путь: API-ключ, бесплатных писем
хватит на группу с запасом. Нужен домен, чтобы письма не улетали в спам; можно начать
с их песочницы.

```
RESEND_API_KEY=re_…
MAIL_FROM=noreply@твой-домен
```

**Вход через Telegram.** Кроме токена нужен `/setdomain` у BotFather — Login Widget
работает только с заранее объявленного домена.

**Подпись сессий.** `SECRET_KEY` — случайные 32 байта, генерю сам, тебе ничего не нужно.
