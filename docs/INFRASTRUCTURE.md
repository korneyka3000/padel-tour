## M2 — база данных

**Рекомендую [Neon](https://neon.tech)**: у тебя уже подключена интеграция с Neon в этой
сессии, значит проект и ветки БД я могу завести сам, без ручной возни. Serverless Postgres,
бесплатного тарифа с запасом хватит.

От тебя: подтвердить, что заводим проект в Neon, и в какой организации.

Что появится:

```
DATABASE_URL=postgresql://…      # прод-ветка
DATABASE_URL_TEST=postgresql://… # ветка для тестов, сбрасывается перед прогоном
```

Локальная разработка пойдёт на SQLite без всякой настройки — Postgres нужен там, где
приложение реально живёт. Схема одна, миграции через Alembic.

**Ветки Neon дают приятный бонус:** можно создавать ветку БД на каждый PR и гонять
миграции на копии реальных данных, а не на пустой базе.

## M3 — Telegram-бот

**Токен получен**, бот живой: **@YoPadelTourBot**. Лежит в `.env`, который в `.gitignore`.

> ⚠️ Токен по ошибке попадал в `.env.example` — файл, который коммитится, а репозиторий
> публичный. В коммит он не ушёл, но раз токен успел засветиться, его стоит провернуть
> у [@BotFather](https://t.me/BotFather) (`/revoke`) и положить новый в `.env`.

Если понадобится завести заново: `/newbot` → имя и username → строка вида `1234567890:AA…`.

Заодно сразу полезно:

- `/setdomain` — понадобится в M5 для входа через Telegram, но проще выставить сразу
- `/setcommands` — список команд, чтобы бот выглядел живым
- **выключить** privacy mode не нужно: бот работает в группе через свои команды и
  инлайн-кнопки, читать чужие сообщения ему незачем

**Webhook.** Настроен на боевой адрес; секрет лежит в переменных Vercel. Перенастроить —
`padel-tour-bot set-webhook https://…`, посмотреть текущее состояние —
`padel-tour-bot webhook-info`, вернуться к polling — `padel-tour-bot drop-webhook`.

Локальная разработка идёт на polling (`padel-tour-bot poll`): туннель ради проверки одной
кнопки — лишняя работа.

**Важно про доступность.** Сервер обращается к `api.telegram.org`, поэтому хостинг должен
стоять там, откуда Telegram доступен. На пользователей в России это не влияет ровно
настолько, насколько у них самих работает Telegram — и именно поэтому веб с входом по почте
(M5) не роскошь, а обязательная вторая дверь.

```
BOT_TOKEN=1234567890:AA…
TELEGRAM_WEBHOOK_SECRET=…   # сгенерирован, лежит в переменных Vercel
```

## M3–M4 — хостинг ✅

Всё на Vercel: фронтенд, API и бот. Neon остаётся снаружи.

### Локальная база

Одна СУБД везде — Postgres. SQLite был дефолтом для свежего клона и стоил дороже, чем
экономил: миграции, которые нельзя выполнить локально, ограничения, которые SQLite
игнорирует, и прогон против базы, которую никто не разворачивает (Р-034, Р-041).

```
docker compose up -d
export DATABASE_URL=postgresql://padel:padel@localhost:55432/padel
uv run alembic upgrade head
```

Тестам это не нужно — они поднимают свой контейнер через testcontainers.

**Боевой адрес:** https://yo-padel-tour.vercel.app, регион `iad1`.

### Почему функция в `iad1`, а не рядом с игроками

Рядом с базой, а не рядом с людьми. Чтение одного турнира делает **пять** запросов к базе;
с функцией во Франкфурте и Neon в Вирджинии это пять пересечений океана на запрос — намерено
790–917 мс против 217 мс на статику с того же edge. Совмещённые, они стоят миллисекунды,
а океан пересекает только сам запрос пользователя: ожидаемо ~330 мс.

Это не лучший из возможных ответов. База в `eu-central-1` с функцией обратно в `fra1` дала бы
~230 мс и вообще перестала бы гонять европейских игроков через Атлантику. Neon не переносит
регион существующего проекта — нужен новый проект и перелив данных (их сейчас около восьмидесяти
строк, дело нескольких минут). **В день, когда база переедет, `regions` надо вернуть в `fra1`,
и не раньше.**
Имя `padel-tour` занято чужим приложением, поэтому `yo-padel-tour` — заодно совпадает
с ботом @YoPadelTourBot.

**Токен не нужен.** Деплой идёт с этой машины по сессии `vercel login`:

```bash
npx vercel deploy --scope korneyka3000s-projects         # превью
npx vercel deploy --prod --scope korneyka3000s-projects  # боевой
```

`VERCEL_TOKEN` понадобился бы только для неинтерактивной среды — например, если решим
деплоить из CI.

**Переменные окружения** (`vercel env ls`): `DATABASE_URL`, `BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET` — заданы для production, preview и development.

**Deployment Protection снята.** По умолчанию Vercel закрывает деплой за SSO, и публичный
сайт отвечал 302 вместо страницы.

## M5 — аккаунты

**Почта — обычный SMTP.** Домен не нужен: для старта подходит Gmail.

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=…
SMTP_PASSWORD=…        # app password, не пароль от аккаунта
MAIL_FROM=…
```

От тебя: **отдельный google-аккаунт** (не основной), включить на нём 2FA и создать app
password. Причина отдельного аккаунта — если Google сочтёт автоматическую рассылку
подозрительной, пострадает вся почта этого аккаунта.

Лимит 500 писем в сутки; нам нужно порядка десятка в неделю.

Без этих переменных приложение поднимается и пишет ссылку для входа в лог, так что
разработка и тесты не блокируются.

**Вход через Telegram.** Кроме токена нужен `/setdomain` у BotFather — Login Widget
работает только с заранее объявленного домена.

**Подпись сессий.** `SECRET_KEY` — случайные 32 байта, генерю сам, тебе ничего не нужно.
