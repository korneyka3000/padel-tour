# M5 — Аккаунты и права: план реализации

> Исполняется в этой же сессии. Шаги с чекбоксами — для отслеживания.

**Цель.** Система узнаёт, кто перед ней: вход по ссылке из письма, приглашение на
конкретного игрока, права на уровне группы и турнира.

**Архитектура.** `Account` — наша личность; всё внешнее (почта, Telegram) — строки
в `Identity(provider, external_id)`. Слой сценариев принимает `actor: Account` и не знает
слова «telegram»; резолвит `telegram_id → Account` бот, на своём краю.

**Стек.** SQLAlchemy 2.0 async, Alembic, FastAPI, `smtplib` через `asyncer.asyncify`,
React 19.

Спек: [`../specs/2026-08-09-accounts-design.md`](../specs/2026-08-09-accounts-design.md)

## Сквозные ограничения

- Реализация на английском: код, докстринги, сообщения об ошибках. Тексты для людей — русские.
- Токены **никогда** не хранятся в открытом виде, только `sha256`.
- Слой сценариев не импортирует ничего телеграм-специфичного. Стережёт `test_layering.py`.
- Функции сценариев не коммитят — транзакцией владеет вызывающий.
- Модели переносимы между SQLite и Postgres; тесты идут на обоих.
- Перед push: `uv run pytest`, `ruff check --no-cache`, `ruff format --check`, `ty check`,
  и прогон на локальном Postgres, если менялась схема.

## Задача 5. Аккаунты, вход и сессии

**Файлы:** создать `src/padel_tour/services/accounts.py`, `tests/services/test_accounts.py`;
изменить `src/padel_tour/services/errors.py`, `__init__.py`.

**Потребляет:** задачи 1, 3, 4.

**Отдаёт:**
```
request_magic_link(session, email, *, mailer, link_base) -> None
redeem_magic_link(session, raw_token) -> Account
open_session(session, account) -> str            # открытый токен для cookie
account_for_session(session, raw_token) -> Account | None
```

      `ensure_identity` дважды подряд даёт **тот же** аккаунт.
- [ ] **Шаг 2.** Прогнать — падает.
- [ ] **Шаг 3.** Реализация. `MAGIC_LINK_TTL = 15 минут`, `SESSION_TTL = 30 дней`,

## Задача 7. Права

**Файлы:** создать `src/padel_tour/services/permissions.py`,
`tests/services/test_permissions.py`; изменить `src/padel_tour/services/tournaments.py`,
`groups.py`.

**Потребляет:** задачи 1, 5.

**Отдаёт:**
```
is_member(session, actor, group_id) -> bool
require_member(session, actor, group_id) -> None
require_owner(session, actor, group_id) -> None
require_organiser(session, actor, tournament_id) -> None
require_can_score(session, actor, tournament_id, round_no, court) -> None
```
Ошибка: `ForbiddenError` (в API → 403).

Меняющие функции турнира получают `actor: Account | None` **после** `session`.
`None` означает «системный вызов» — CLI и миграции; проверок нет.

- [ ] **Шаг 1.** Тесты: посторонний не завершает чужой турнир; игравший вводит счёт
      своего матча; неигравший участник — не может; организатор может везде; владелец
      группы перехватывает турнир; турнир без организатора (из CLI) открыт всем.
- [ ] **Шаг 2.** Прогнать — падает.
- [ ] **Шаг 3.** Реализация; протянуть `actor` через `start_tournament`,
      `reroll_tournament`, `record_score`, `amend_score`, `advance_round`,
      `finish_tournament`, `add_player`, `rename_player`, `deactivate_player`.
- [ ] **Шаг 4.** Прогнать весь набор — старые тесты чинятся передачей `actor=None`.

## Само-ревью плана

**Покрытие спека.** Модель — 1, миграция — 2, вход по почте — 3–5, приглашения — 6, права
— 7, видимость и API — 8, бот-адаптер — 9, веб — 10, проверка — 11. Требование «токены
только в виде хеша» закрыто задачей 3 и используется в 5 и 6. Требование «сценарии не знают
слова telegram» проверяется в задаче 11.

**Заглушек нет.** Все шаги называют конкретные файлы, имена функций и условия тестов.

**Согласованность имён.** `LoginSession` (не `Session`) везде; `actor` — единое имя
параметра; `ForbiddenError` → 403 в одном месте, в `app.py`.
