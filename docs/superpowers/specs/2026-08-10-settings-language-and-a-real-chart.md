# M6.5 — Настройки, языки и настоящий график

**Дата:** 2026-08-10 · **Статус:** сделано

## Зачем

Четыре долга, накопившихся к концу M6. Ни один не блокировал веху, все четыре видны
пользователю или тому, кто будет это чинить в три часа ночи.

1. Конфигурация читается россыпью `os.environ.get` — без типов, без валидации, опечатка в
   имени переменной тихо даёт дефолт
2. Сообщения об ошибках написаны по-русски прямо в коде, вперемешку с английскими
   докстрингами. Правило проекта — английский в реализации — на них не распространили
3. Интерфейс говорит только по-русски, и русский вшит в TSX
4. «График» в боте — это таблица чисел и строка `3→2→2→1`. Движение по ней не читается

## Что не входит

Переезд почты на Resend (нужен домен), подтверждение результатов (M7), живая страница (M8).

## Решение 1 · Один типизированный `Settings` вместо десяти `os.environ.get`

`pydantic-settings` читает `.env` сам, поэтому `python-dotenv` уходит из зависимостей
целиком — он и так использовался в одном месте, в конфиге бота.

Тонкость, из-за которой нельзя завести модульный синглтон: `base_url()` и
`mailer_from_env()` читают окружение **в момент вызова**, и два с лишним десятка тестов на
этом стоят — они подменяют переменные через `monkeypatch` уже после импорта.

Первым заходом я закешировал `Settings` через `lru_cache` со сбросом для тестов. Это
сломало четыре теста вебхука: `settings()` успевал вызваться фикстурой базы **раньше**, чем
тест доходил до своего `monkeypatch.setenv`, и запрос видел старое окружение. Двадцать семь
мест, где тесты трогают переменные, пришлось бы научить сбрасывать кеш — и не забывать этого
в каждом новом тесте.

Замер вместо предположения: построение `Settings` стоит **111 мкс** без файла и **182 мкс**
с `.env`, при одном-трёх вызовах на запрос. Кеш покупал полмиллисекунды и продавал целый
класс ошибок «окружение говорит одно, процесс верит в другое». Кеша нет.

Отдельно — **`.env` не читается в тестах**. Раньше `dotenv` грузился только в конфиге бота,
и прогон файла не видел; с общими настройками увидел бы. В копии разработчика лежат живой
токен бота и строка подключения к проду, так что тест мог бы туда дотянуться — тихо, на
машине, где всё выглядит нормально. Какой файл читать, решает модульная константа `ENV_FILE`,
и `conftest` ставит её в `None`.

## Решение 2 · У ошибки есть код, и он машинный

Правило «всё в реализации по-английски» распространяется на сообщения. Но английский текст
нельзя показывать русскому пользователю, а значит одного перевода строк мало — нужен способ
сказать то же самое на языке читателя.

Код выводится **из имени класса**, а не заводится руками:

```python
PlayerAlreadyClaimedError  →  "player_already_claimed"
NotSignedInError           →  "not_signed_in"
```

Ручной реестр разошёлся бы с классами при первом же переименовании; выведенный код
разойтись не может. Параметры, которые нужны в тексте, едут отдельным полем, а не внутри
строки — иначе клиент не сможет собрать фразу по своим правилам согласования:

```jsonc
{
  "detail": "Аня is already taken",   // английский, для логов и разработчика
  "code": "player_already_claimed",
  "params": { "name": "Аня" }
}
```

Клиент переводит по коду и **откатывается на `detail`**, если код незнаком. Это не
формальность: старый фронт против нового бэкенда встретит коды, которых у него нет, и лучше
показать английскую фразу, чем пустоту.

Ошибки движка (`PadelEngineError`) получают то же обращение — они уже английские, им нужен
только код.

## Решение 3 · Словарь, а не библиотека

`react-i18next` под две локали — это рантайм, плагины и конфиг ради `t('key')`. Вместо него
объект и функция, а типы обеспечивают то, ради чего библиотеку обычно и берут:

```ts
export const ru = { 'nav.signIn': 'Войти', … } as const
export const en: Record<keyof typeof ru, string> = { … }
```

Пропущенный ключ в `en` — ошибка компиляции, а не пустая строка в проде.

Числительные — `Intl.PluralRules`, даты — `Intl.DateTimeFormat`. Наш `plural()` с ручным
разбором последних двух цифр уезжает: он был написан только под русский и в английском врёт.

Язык: сохранённый выбор → `navigator.language` → русский. Переключатель в шапке.

## Решение 4 · График рисуется, а не печатается

`chart_screen` печатает накопленные очки колонками и путь по местам строкой. Это таблица.

Бот получает **PNG**, отрисованный Pillow, и кнопку «Открыть в вебе» рядом. Почему так:

- **Pillow, не matplotlib.** Бот в проде живёт внутри той же serverless-функции, что API;
  matplotlib с numpy — это десятки мегабайт в бандл ради одного экрана. Pillow ~4 МБ, и
  рисовать линии по точкам мы умеем сами
- **Шрифт едет в репозитории.** Pillow своих шрифтов не носит, системные на Vercel
  непредсказуемы, а имена у нас кириллические. Кладём Golos Text (OFL) — тот же шрифт, что
  в вебе, 180 КБ. График будет выглядеть как продукт
- **Рисуем места, а не очки.** Очки монотонно растут, и восемь почти параллельных линий
  ничего не сообщают. Место скачет — а вопрос, который задают графику, звучит «когда я
  просел»

Экран турнира — текстовое сообщение с клавиатурой, и он такой один на чат по устройству
M3. Фотографию нельзя дорисовать в текстовое сообщение, поэтому график **заменяет** медиа
этого сообщения через `editMessageMedia`, а подпись несёт клавиатуру и краткую таблицу.
Возврат на любой другой экран возвращает сообщение к тексту.

Ограничение подписи — 1024 символа. Таблица на 8 игроков в неё влезает; на 24 — нет,
поэтому в подписи только тройка призёров и напоминание, где полная.

## Порядок

Настройки → коды ошибок → языки → график. Языки зависят от кодов; остальное независимо.

## Готово, когда

`python-dotenv` нет в зависимостях, конфиг читается одним объектом, и тесты по-прежнему
подменяют окружение. Ни одной русской строки в `src/`. Интерфейс переключается между
русским и английским, включая тексты ошибок с сервера. Бот на кнопке «График» показывает
картинку, с которой видно, кто когда просел, и кнопку на веб-страницу. Зелено на SQLite,
на Postgres и во фронте.
